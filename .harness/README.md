# 项目 Harness

## 开工顺序

1. 读 [AGENTS.md](../AGENTS.md) 确定改动边界，再读 [当前任务](CURRENT.md) 找到状态、证据和下一步。用户最新要求优先于历史待办。
2. 按任务读 [功能地图](../FEATURE_MAP.md) 和对应源码。需要启动、导出或部署时查 [README](../README.md)。需要理解历史决策或线上基线时查 [项目交接](../PROJECT_HANDOFF.md)。
3. 从 [验证入口](VERIFY.md) 选择能证明本次验收条件的检查。写入操作用隔离数据。没有可用工具时记录具体限制。

功能地图维护源码定位，README 维护使用方式，项目交接保留历史与部署记录。当前任务页只维护正在处理或待交接的工作，并链接上述来源。

## 写回时机

- 开始或接手时更新目标、范围、状态和下一步。已有待办保留到完成、取消或明确移交。
- 状态变化、新发现改变下一步、遇到阻塞，或一段工作暂停、交付时，在当前任务页写回。记录具体文件、实测结果与剩余事项，使接手者能直接行动。
- 完成后将需长期保留的变更和验证摘要写入项目交接，再把当前任务页的详细证据链接到交接。源码定位或公开使用方式变化时，分别更新对应文档。

任务状态使用「待做」「进行中」「待验证」「阻塞」「已完成」。每项检查独立写明「通过」「失败」「未执行」，并说明验证的是本地、CI 还是线上。验证标准见 [验证入口](VERIFY.md)。

仓库和镜像公开。记录命令、版本、匿名结果和可公开的日志链接。密码、会话、私有文章、实际数据文件和后台截图留在受控环境中。
