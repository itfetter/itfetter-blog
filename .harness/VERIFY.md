# 验证入口与证据

| 改动 | 现有入口 | 可确认的结果 |
| --- | --- | --- |
| 前台、后台和编辑器 | Windows 运行 `start-preview.bat`，默认打开 `http://127.0.0.1:8081/`，写作台入口为 `/admin`。需要写数据时，为 `BLOG_DATA_DIR` 指定预先创建的临时目录，再用 `python -B server.py --port 8081` 启动。端口占用时改用空闲端口。 | 按 [功能地图](../FEATURE_MAP.md) 运行受影响的操作，记录浏览器、视口、输入与实际反馈。 |
| JavaScript | `node --check admin.js`、`node --check markdown.js`；以 Node 的 `vm.Script` 逐段解析 `index.html` 内联脚本。 | 语法可解析。 |
| Python 与持久化 | 用已有 Python 的 `ast.parse` 检查编辑过的模块。启动隔离实例，通过真实 HTTP 和重启验证受影响的读写行为。 | 分别记录语法、HTTP 状态和重启后读回结果。 |
| 容器与发布 | [GitHub Actions](../.github/workflows/publish-image.yml) 构建镜像，冒烟检查 `/content.js` 可访问且未登录 `/admin/content` 返回 401，再发布镜像。部署方式见 [README](../README.md)。 | 附运行链接或镜像摘要。线上需另记更新后的实际运行版本、容器健康和相关请求结果。 |

当前没有独立自动化测试套件。标记「通过」需记录检查对象、版本或本地文件摘要、命令或复现步骤、环境和观察到的结果。引用既有实测时注明证据出处与覆盖范围；本轮复跑单独记录。静态语法结果、浏览器交互、镜像冒烟和线上健康各自只覆盖所列目标。缺少条件的检查记「未执行」并写明下一步。测试范围内全部验收项有结果后方可标记「已完成」；部署是否属于验收项按当前任务约定。
